# 시연 영상 장면표 — `docs/demo/video/nextstop-demo.mp4`

목표: 처음 보는 심사위원이 **30초 안에 무슨 앱인지 알고**, 끝까지 끊김 없이 본다.
첫 화면: `video/nextstop-demo-poster.png`(3초 지점). 영상 정보: 85초, 1920×1080, 60fps, H.264 + AAC, 메타데이터 비움. 한국어 내레이션과 배경음악(-20dB 안팎, 끝에서 페이드아웃)이 들어 있다.
대본은 [narration.txt](narration.txt)에 있다. 장면 경계는 내레이션 음성의 쉼에서 쟀다.
8번 문장은 사실에 맞게 고친 음성(`scene8_fix.mp3`, 7.63초)으로 바꿨다. 기어는 Pleos SDK가 아니라 AAOS 표준 Car API로 읽기 때문이다. 9번부터는 1.16초 뒤로 밀렸다.

## 화면 출처 표기

화면 오른쪽 위에 항상 출처를 적는다. 실제 동작과 다른 장면은 반드시 표기한다.

| 표기 | 뜻 |
|---|---|
| 실제 화면 · Pleos Connect 공식 에뮬레이터 · Virtual Console로 기어·문 조작 | CI(GitHub Actions)에서 공식 에뮬레이터를 띄우고, Virtual Console로 기어·운전석 문을 바꾼 녹화(`ci-20261030-0418/vc-drive-clean.mp4`)에서 뽑은 장면 |
| 실제 화면 · Pleos Connect 에뮬레이터 · NaviHelper로 목적지 전달 | 노트북 실측(10/30)에서 앱이 `requestRoute`를 보내 Pleos 내비가 목적지를 띄운 화면(`20261030-auto-host/demo-3-next.png`) |

| 연출 장면 · 설명 그래픽 | 앱 화면이 아닌 그림 |

- 첫 30초 안에 문제(0:00), 이름과 가치(0:08), 핵심 동작 P → 문 → D = 완료 + 다음 집 내비(0:16~0:29)가 모두 나온다.
- 렉을 없앤 방법: 원본 녹화는 초당 10장(CI)이거나 화면이 바뀔 때만 찍힌 것(노트북)이다. 그래서 동영상을 그대로 틀지 않고, 단계마다 가장 선명한 장면을 골라 60fps로 천천히 확대하고 교차 전환으로 잇는다. 앱 화면 안의 글자는 원본 그대로다.
- 자막: 화면 아래 큰 글자(50px), 내레이션 문장 단위. 음성의 '피'·'디'는 P·D로, '플레오스'는 Pleos로 적었다.

## 다시 만들기

소스는 [video/remotion/](video/remotion/)에 있다(Remotion, 로컬 렌더, 지출 0).

```
cd docs/demo/video/remotion
npm install
copy <음성 폴더>\narration.mp3 public\ & copy <음성 폴더>\scene8_fix.mp3 public\ & copy <음성 폴더>\music.mp3 public\
npx remotion render src/index.jsx NextStopDemo out.mp4 --codec=h264 --crf=18 --audio-codec=aac
```

음성·음악 파일은 저장소에 넣지 않는다(외부 도구로 만든 파일이라 원본은 작업 폴더에만 둔다).
Windows에서 저장소 경로가 길면 Remotion이 받은 브라우저가 실행되지 않는다. 그럴 때는 `--browser-executable`로 설치된 Edge나 Chrome을 지정한다.
렌더한 뒤 `ffmpeg -i out.mp4 -map_metadata -1 -fflags +bitexact -c copy nextstop-demo.mp4`로 메타데이터를 비운다.
