# 시연 대본 (12/3~4 오프라인 PT, 에뮬레이터 실시연)

심사위원이 기억할 한 장면: **"문 닫고 D 넣으니 다음 집이 떴다."**
나머지는 그 장면을 위한 준비와 그 장면 뒤의 숫자(시간당 실수익)다.

|---|---|---|---|

## 1인 발표 운영(개인 참가)

말하는 사람과 조작하는 사람이 같다. 손이 꼬이지 않게:
- 화면 왼쪽에 에뮬레이터, 오른쪽에 Virtual Console(기어·도어 카드만 보이게 스크롤해 둔다). 조작은 클릭 한 번씩이라 말하면서 가능.
- 말이 길어지는 구간(0:00~0:40, 2:20~)은 조작이 없다. 조작 구간(1:00~2:20)은 말을 짧게.
- 조작이 막히면 아래 '현장 장비 조합'의 다음 줄로 바로 내려간다. 말은 끊지 않고 같은 대본을 이어 간다.

## 현장 장비 조합(시연 경로: 본선 C, B 예비)

> **11/2 갱신 — 아래 표의 '2번 기본(영상 재생)'은 더 이상 기본이 아니다.** 공식 공지('참가 및 출품 유의사항' 2절)가 PT 대상 팀에 **실제 동작 가능한 앱 시연(에뮬레이터 구동 화면 또는 기기 시연)을 필수**로 요구한다. 현장 순서·전환 대본·위험 대응은 [`../pt/시연_운영.md`](../pt/시연_운영.md)가 원본이다(기본 = 노트북 공식 에뮬레이터를 발표 직전 Cold boot + 시연 신호 모드, 영상은 실패 때 예비). 아래 표는 10/30 기록으로 남긴다.

노트북에서 공식 에뮬레이터를 오래 띄우는 길(A)은 실패로 판정했다(부팅 5~8분 뒤 차량 HAL이 멈춤, 신호 지연 12~28초).
그래서 같은 3분 대본을 장비에 따라 아래 셋 중 하나로 한다. 주최 측 공식 안내가 오면 그에 따르고, 안내가 없으면 2번(기본)을 준비해 간다(1·3번 준비물도 함께).

| 조합 | 화면 | 조작 | 대본에서 달라지는 것 |
|---|---|---|---|
| 1. 주최 측 GPU PC 제공 | 그 PC의 공식 에뮬레이터 + Virtual Console | 사람이 클릭(위 표 그대로) | 없음. 예비로 C 녹화본을 USB에 |
| 2. **기본**: PC 없음 | 시연 영상(`docs/demo/video/nextstop-demo.mp4`, 85초, 내레이션 포함) 재생 | 재생만 | 영상에 내레이션이 있으니 재생 중에는 말하지 않는다(시작 전 한 줄: "실제 Pleos 공식 에뮬레이터 화면입니다"). 영상이 끝난 1:25쯤부터 3:00까지는 정산 화면을 띄워 숫자·기술 설명(대본 2:20~). 질문이 오면 노트북 B |
| 3. 노트북까지 멈춤 | C 녹화본만 | 재생만 | B 질의응답 생략 |

노트북 B(시연 신호 목업)를 쓸 때:
- 시연 직전에 Cold boot한다. 부팅 몇 분 뒤 시스템이 멈춘 기록이 있어(10/30, 4분·5~8분) 미리 켜 두지 않는다.
- `scripts\demo\demo.ps1 -Launch -Stops 2 -GapSec 3`(시연 신호 자동 재생, 손 안 씀) 또는 화면 우하단 시연 패널.
- 화면에 '시연 신호' 표시가 뜬다. "실제 차량 신호는 녹화본에서 보신 그대로"라고 한 줄 덧붙인다.

## 조작 경로(실측 결과로 결정)

1. **Virtual Console** — 실측에서 기어·문 PASS면 이것을 쓴다(가장 설득력 있음). `adb forward tcp:8088 tcp:8088` 후 브라우저 `http://127.0.0.1:8088/`, 첫 화면에서 기어는 속도계 옆 `P R N D`, 운전석 문은 BODY 카드의 `FL door`(누를 때마다 열림↔닫힘). 시작 전에 `State`에서 `bridge_ready: true`를 확인(`docs/pleos/virtual-console.md`).
2. ~~adb VHAL 주입~~ — Pleos 이미지 v2.1.0은 user 빌드라 막혀 있다(CI 실측 2026-10-30). userdebug 이미지가 나오면 `scripts/demo/demo.ps1 -Mode vhal`
3. **앱 시연 신호** — 화면 우하단 시연 패널(P / 문 열기 / 문 닫기 / D) 또는 `scripts/demo/demo.ps1 -Mode broadcast`

## 리허설 체크리스트("시연 점검")

공식 에뮬레이터에서 C·B를 한 번씩 돌린 결과(장면별 시간·끊김·실패 지점): `docs/demo/rehearsal-20261030.md`. 같은 리허설을 다시 돌리려면 커밋 메시지에 `[rehearsal]`.

- [ ] 에뮬레이터 Cold Boot로 기동, Pleos 내비가 기본 내비로 설정돼 있음
- [ ] **부팅 직후 Pleos 내비가 스스로 앞으로 나와 지도를 불러온다 → 로딩이 끝난 뒤 앱을 연다.** 앱이 덮인 채 '운행 시작'을 누르면 먹지 않는다(10/30 리허설 1회차)
- [ ] `adb install -r apk/NextStop_다음집_release.apk`
- [ ] 앱 실행 → 계획 화면에 동선 그림 표시
- [ ] 운행 시작 → 내비 목적지가 1번으로 설정 → 내비가 앱을 덮으면 앱으로 돌아오는 손동작 확인(리허설에서는 처음에만 덮었다)
- [ ] P·문·문·D로 완료 확인이 1.2~1.4초 안에 끝나고 다음 집 표시 (음성은 선택 기능, 기본 꺼짐 — 시연은 화면만으로)
- [ ] 문 없이 P→D는 완료가 안 됨
- [ ] 5건을 모두 완료해야 정산이 뜬다 — 2:00~2:20 안에 남은 건 끝내기 연습
- [ ] 정산 화면 숫자 확인(계기판 실측 km·순수익, 30분 미만이면 시간당 대신 안내 문구)
- [ ] 예비: 시연 패널(`--es mode demo`)로 같은 흐름이 되는지
