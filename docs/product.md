# 제품 설계 노트

## 누구를 위한가

자기 차로 택배·배송 부업을 하는 사람. 차량이 업무 도구지만, 차는 업무를 모른다.
하루 수십 곳을 돌며 ① 순서 짜기 ② 내비 입력 ③ 완료 체크 ④ 정산을 폰과 머리로 따로 한다.

## 핵심 아이디어: 차량 신호 = 업무 체크포인트

배송 1건은 차에서 늘 같은 신호 순서로 나타난다.

```
주행(D) → 정차(P) → 운전석 문 열림(하차) → 문 닫힘(승차) → 출발(D)
```

이 순서를 상태기계로 판정하면 **화면을 만지지 않고** 완료가 기록된다. 위치(GPS)를 쓰지 않으므로
지하주차장·아파트 단지 안·터널에서도 흔들리지 않고, 위치 권한도 필요 없다. 차량용 앱이어야만 가능한 기능이다.

오탐 방지 규칙(단위 테스트로 고정):
- 신호 대기·잠깐 정차(P 후 문을 안 열고 D) → 완료 아님
- 출발지 상차(운행 시작 후 첫 D 전의 P·문) → 완료 아님
- 문 열린 채 D → 완료 아님
- P에서 R로 후진 출차 후 D → 완료
- 주행 중 문 신호 → 무시

## 화면 원칙

- 주행 중: 다음 배송지 1줄 + 남은 건수 1줄, 104sp/52sp, 버튼 없음(CarUxRestrictions + 기어 기준)
- 정차 중: 다음·그다음 배송지, 힌트("문을 닫고 D를 넣으면 완료"), 수동 완료·나중에·건너뛰기
- 내비가 앞에 있을 때(목적지를 넘기면 Pleos 내비가 앱을 덮는다 — 에뮬레이터 실측): 1건 완료를 헤드업 알림 한 줄로("✓ 2/5 완료 · 다음 집 · ○○", 소리·진동·움직임 없음). 앱이 앞에 있으면 알림 대신 아래 연출.
- 전환 연출(약 1.4초): 초록 플래시 + 체크 + 완료 카운트 n-1→n + 다음 집 카드 슬라이드 + 음성 안내.
  D를 넣은 직후 아직 정차 중인 순간에 끝나도록 짧게.

## 사업성 방향(검토용)

중심은 **'문 닫고 D → 다음 집' 자동 체크포인트**다. 운행기록 앱(법인차 운행일지 등)은 '주행을 기록'하는 데서 끝나지만,
다음집은 차량 신호로 **업무(배송 1건)의 경계를 자동으로 잘라 내고 다음 행동을 바로 연결**한다. 운행기록은 그 부산물일 뿐이다.

- **실수익 가시화**: 건당 단가만 보던 부업자가 연료비·시간을 뺀 시간당 실수익을 보고 지역·시간대를 고른다.
- (보조) **운행기록 내보내기**: 개인사업자 차량 경비 처리에 필요할 때 계기판 실측 기록을 내보낸다(세무 판단은 하지 않음).
- **확장**: 전기차 전비(같은 정산식, 단위만 kWh), 시간 지정 배송 우선순위,
  체크포인트 신호 보강 — 운전석 착석 해제(Seat Occupancy)·비상등(Hazard)을 '하차·배송 정차' 보조 신호로(Virtual Console에 카드 있음),
  FusedLocation Proximity Alert로 '도착 임박' 안내(실차 전용).
- 수익 모델 후보: 기본 무료 + 월간 리포트/운행기록 내보내기 유료, 차량 앱 마켓 기본 제공 제휴.
  (시장 규모 수치는 출처 확인 후 기획서에 넣는다 — 이 문서에는 근거 없는 수치를 적지 않는다)
