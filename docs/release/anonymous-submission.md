# 익명 제출 절차 (11/12 전후, 한 번에)

지금 저장소의 이력은 그대로 둔다. 제출 직전에 **익명 계정/조직의 새 저장소**로, **익명 작성자 커밋 1개**짜리 깨끗한 이력을 올린다.

## 0. 미리 준비 (사람)

| # | 할 일 | 비고 |
|---|---|---|
| 1 | 제출용 GitHub 계정 또는 조직을 만든다 | 이름에 실명·학교·학번·기존 계정명을 쓰지 않는다(예: 팀/서비스 이름). 프로필 이름·소개·사진·위치·링크는 비워 둔다 |
| 2 | 그 계정의 이메일 공개 끄기 | Settings > Emails > Keep my email addresses private |
| 3 | 비공개 저장소 `next-stop` 생성(빈 저장소, README 없이) | 설명(description)·토픽에도 개인 정보 금지 |
| 4 | 개인 정보 패턴 파일 만들기: `~/.nextstop-anon-deny.txt` | **저장소 밖**에 둔다. 한 줄에 하나(정규식, 대소문자 무시): 실명(한글·영문), 학교명(한·영·약칭), 학번, 기존 GitHub 계정명, 이메일, 전화번호 |

패턴 파일 예시(값은 직접 채운다):

```
# 이름
홍길동
Gil-?dong
# 학교
OO대학교
OO University
# 학번·계정·연락처
20XX12345
old-account-name
someone@example\.com
(^|[^0-9])010-?[0-9]{4}-?[0-9]{4}([^0-9]|$)
```

패턴 고르는 요령(10/30 리허설에서 확인):
- 두 글자 약칭이나 영문 네 글자 약칭은 코드·문장 낱말 안에 섞여 오탐이 수십 건 나온다(예: 영문 약칭이 `mainHandler` 같은 이름 안에 들어간다). 학교명은 '…대'·'…대학교', 영문은 '… univ'처럼 붙여 쓴다.
- 전화번호는 앞뒤가 숫자가 아닐 때만 잡게 쓴다. 그렇지 않으면 실측 로그의 타임스탬프·메모리 주소가 걸린다.
- 저장소에 없어야 할 내부 운영 낱말(개인 작업 공간 이름 등)도 같이 넣어 두면 문서 섞임을 잡는다.

## 1. 원본 점검

노트북(Git Bash) 또는 클라우드 세션에서:

```bash
scripts/release/anon-check.sh
```

원본 저장소에서는 **'익명 작성자가 아닌 신원'과 '세션 링크 트레일러' 항목이 나오는 게 정상**이다(최초 커밋·이력 때문). 새 이력에서 사라진다.
그 밖의 항목(파일 내용·APK·이미지)에서 문제가 나오면 원본에서 고치고 커밋한 뒤 다음 단계로.

## 2. 익명 이력 만들기 + 점검

```bash
scripts/release/anon-export.sh https://github.com/<제출용 계정>/next-stop.git ../next-stop-submission
```

- 현재 커밋의 **추적 중인 파일만** 복사(`.probe-cache/`, `demo-output/`, `local.properties` 등은 빠짐).
- `next-stop-dev <dev@next-stop.invalid>` 작성자로 커밋 1개 + 태그 `submission-YYYYMMDD`.
- 새 이력을 자동 점검하고, 통과하면 푸시 명령을 알려 준다(`--push`를 세 번째 인자로 주면 바로 푸시).
- 계정이 없어도 리허설할 수 있다: 주소 자리에 `https://example.invalid/anon/next-stop.git`, 출력 폴더는 저장소 밖 임시 폴더. 푸시하지 않으니 바깥에 아무것도 나가지 않는다.

## 3. 새 저장소에서 (사람)

| # | 할 일 |
|---|---|
| 1 | Actions가 켜져 있는지 확인 → `build` 워크플로가 초록인지 확인 |
| 2 | 필요하면 커밋 메시지에 `[publish-apk]`를 넣어 APK·스냅샷을 다시 게시(작성자는 워크플로가 `next-stop-dev`로 고정) |
| 3 | 심사용 계정을 Collaborator로 초대(공모전 안내 계정) |
| 4 | 접수양식에 새 저장소 주소 기입 |

## 최종 익명 점검표

`anon-check.sh`가 자동으로 보는 것과 사람이 봐야 하는 것.

| 대상 | 자동 점검 | 사람 확인 |
|---|---|---|
| **커밋** | 모든 작성자·커미터가 `next-stop-dev`, 메시지에 패턴·세션 링크 없음, 과거 커밋 파일까지 검색 | — |
| **태그** | 태그 작성자가 익명 | 태그 메시지 |
| **APK** | 내부 모든 파일에 패턴·빌드 PC 사용자 경로(`C:\Users\…`, `/Users/…`) 없음, 서명 인증서 DN에 패턴 없음 | 앱 이름·아이콘·화면 문구 |
| **README·문서·코드** | 추적 중인 모든 텍스트 파일, 파일 이름·경로, 사용자 홈 경로 | 문장 속 간접 정보(학과·지역·군 경력 등)가 없는지 한 번 읽기 |
| **영상**(`*.mp4`) | 인코더 기술 정보(`major_brand`·`encoder` 등) 말고 남은 태그(촬영 시각·기기 버전·제목·위치) — `ffprobe` 필요 | 화면 속 계정·알림·바탕화면 |
| **스크린샷·이미지** | PNG 텍스트 청크·EXIF 존재 여부 | 화면 속 계정·알림·시계 등 |
| **실측 결과**(`docs/probe-results/`) | 위 텍스트·이미지 점검에 포함 | 스크립트가 사용자 이름을 `<user>`로 바꿨는지 |
| **원격 주소** | origin에 패턴 없음 | 저장소 설명·토픽·계정 프로필 |
| GitHub 쪽 | — | Actions 로그·아티팩트는 새 저장소에서 새로 생김(옛 로그 없음), Issues/PR 이력 없음, 계정 이메일 비공개 |

## 하지 않는 것

- 원본 저장소의 이력을 다시 쓰지 않는다(강제 푸시 없음). 원본은 개발용으로 그대로 둔다.
- 패턴 파일을 저장소에 넣지 않는다(스크립트가 저장소 안 경로면 실행을 거부한다).
